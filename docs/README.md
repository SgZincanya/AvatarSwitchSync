# Avatar Switch Sync 0.8.1

一个用于 VRChat 的模型设置共享工具。切换同一共享组中的模型后，自动恢复选定的参数状态。

## 快速开始

1. 运行安装包，跟随简体中文向导安装；也可解压便携分发包，运行 `AvatarSwitchSync.exe`，保留旁边的 `_internal` 文件夹。
2. 在 VRChat 中启用 OSC，分别加载要共享设置的模型。
3. 点击「新建共享组」，填写名称，选择至少一个参考模型。
4. 检查共享参数，点击左侧「开始共享」。

打开窗口不会自动开始共享。每次点击开始共享时，先读取当前模型的实时值并更新共享记录，随后可在同组模型之间恢复。组外模型不参与。

分组可以只包含一个参考模型。先开始共享，保存参考设置，再用添加模式逐个加入新模型。成员区默认折叠，点击“成员 · 数量”展开；每个成员独占一行，多成员时可滚动查看。

## 添加模式

先在左侧选中目标共享组，点击「开启添加模式」。共享运行中可以直接开启；停止状态也可以开启并连接游戏，无需先切回旧模型。此模式需要目标组已经保存过共享记录。

之后在游戏里依次使用新模型。模型稳定且本地参数、保存记录准备好后，会自动加入开启时选中的组，并应用该组已有的共享设置。界面会显示添加目标和添加结果，无需停止共享或手动编辑分组。缓存迟到时会继续等待，无需再次换模；属于其他组的模型会跳过，不会自动移组。

添加模式保留原组的参数选择，不自动扩大共享范围；新成员缺少或类型不兼容的参数仍会在整个组中隐藏并忽略。衣服排除与实时眼追保护继续生效。点击「退出添加模式」后继续普通共享，不再自动加入模型；停止共享或关闭软件也会退出添加模式。

添加模式使用已有共享记录，不会把新模型默认值当作新记录覆盖原设置。普通「开始共享」依然先保存当前游戏值。首次使用新分组时，请先用参考模型开始共享一次以建立记录。

## 开始时保存当前值与恢复结果

每次点击开始共享后，在首个组内模型稳定约 3 秒并可读取时，软件先保存独立快照，再将当前游戏中已勾选且可读写的共享参数保存为最新共享记录。保存成功后继续同步；本次开始不会用旧共享值覆盖当前模型。之后切换到同组模型时，恢复这份最新记录。不可读、未勾选和受保护项不会覆盖历史值，其他组的记录保留。如果备份或共享记录保存失败，本次共享停止。

「参数快照」中会标注自动备份和手动快照。自动备份只保留最近 20 份，手动快照长期保留；查看快照不会自动写回模型。

恢复完成后，状态栏分别显示已确认、跳过和未确认的参数数量，未确认项保留原共享记录。

## 校准与批量归零保护

软件可读取到 `TrackingType`、`VRMode` 或 `IsAnimatorEnabled` 时，用它们辅助识别初始化或动画器停用状态，期间暂停共享记录和恢复。相关状态恢复并稳定 3 秒后，再等待模型稳定并恢复原共享值。这些信号不保证所有模型均通过 OSC 提供，也不是专用的全身校准开关。

缺少相关信号时，软件会拦截相对最近已接受状态同时归零的至少 3 项、且达到原非零项 60% 的变化。疑似归零状态不会因超时自动采纳；受影响值恢复并稳定后才继续。若这是主动批量重置，请停止后重新开始共享，明确采纳当前游戏值。正常将单项参数改为 0 或关闭仍可保存。

参数变化稳定约 2 秒后才进入共享记录，避免短暂归零污染记录。校准保护不能修复已经被覆盖的历史记录，也不能识别所有没有状态信号的校准情况；可在运行记录查看是否触发保护。

## 性能与运行诊断

稳定共享阶段不轮询完整参数表，不重发参数。选定参数变化通知到来后才更新记录，相同值不会唤醒共享线程；仅每 5 秒读取一次模型标识，用于发现断线或遗漏的换模通知。切换模型、加载和恢复期间才读取完整参数表并恢复共享设置。共享记录变化后合并写入磁盘，停止时保存已确认的变化。

参数表只更新变化的数值，日志按批追加。左侧「运行诊断」仅在打开时采样，显示本软件 CPU、内存、读取耗时、完整校验频率和收发数据包数量。CPU 按全机核心数折算，数值不能代替游戏帧率测试。诊断不上传数据。

## 新模型发现

左侧「本机模型」显示所有已发现的模型，按缓存更新时间排序，支持名称与 ID 搜索，并显示参数数量、保存项数量和资料状态。

Windows 上通过目录变化通知发现模型缓存更新，无变化时不反复扫描；目录尚不存在或通知不可用时每 10 秒回退检查，新模型出现后无需重启。新建、编辑分组时也会重新扫描；已经打开的分组选择窗口会接收新模型，同时保留你当前勾选。

顶部和分组编辑窗口都提供「刷新模型」。刷新是本地读取操作，运行共享时也可以使用。

模型仅上传到 VRChat 并不足以出现在本地列表：需在游戏里实际加载模型并开启 OSC。已生成 OSC 缓存但尚未产生保存记录的模型也会显示为「等待保存记录」，不再被误认为未发现。保存记录损坏时仍保留模型条目，并显示资料暂不可读。

## 分组和参数

- 分发包不预设任何角色、模型 ID、分组或个人保存值。首次打开显示空白引导页。
- 可新建、重命名、编辑成员和删除分组；一个模型只能加入一个组。修改自动保存。
- 可以搜索参数原名或简化后的显示名称，筛选共享项、未共享项和受保护项。
- 点击「共享」列或按空格切换；支持多选后批量共享或排除。
- 参数列表显示各项在组内模型的覆盖数量，以及已保存的共享值。选择行可查看原名、排除原因和数据来源。
- 「更多 → 刷新模型与参数」保留已有勾选和自定义映射，补入新发现的候选项。
- 运行中可查看参数和日志，编辑在停止共享后开放。

仅显示组内**全部模型均存在、均有本地保存记录且收发类型一致**的参数。某个模型没有的项默认隐藏，整个组都不记录、不恢复该项，即使旧配置曾勾选也会忽略。缺少某个组员的本地缓存时，暂不共享该组的参数；加载模型后刷新即可重新判断。旧配置和历史值保留，不会因隐藏而删除。

这些本地记录并非当前 Unity 构建的 Saved 标记证明。运行时 OSCQuery 不可读写的项也会跳过。

衣服按名称筛选，重置和实时追踪参数受到保护；通用规则不是语义识别，自动命名的功能仍需检查。工具尚未包含 Unity 菜单导出或可靠的跨构建功能映射，简化名称只移除显示噪声，不会猜测参数用途。

## 眼追与 OSC

独立 OSCQuery 连接使用自动分配的端口，不绑定 9000/9001，不修改 VRCOSC 或 VRCFaceTracking 配置，不接管眼追数据。

实时眼球和表情参数受保护，不向 `/tracking/eye/*` 写入。已知的眼追启用、嘴追启用和平滑度等静态 Saved 设置可参与共享，只在恢复阶段写入。保存的眼追开关为关闭时，恢复后也会关闭眼追，这是该设置的实际效果。

## 手动参数快照

点击窗口右上角「保存当前参数表」，读取当前 VRChat 模型的完整 OSC 参数表并保存到软件内。无需先创建分组或开始共享。

点击左侧「参数快照」可按时间选择历史记录，搜索查看参数名、类型、当时的值和本地保存记录标记。软件重启后仍可查看；可同时保存多份，旧快照不会被覆盖。

快照包含当前模型的全部可见 OSC 参数，包括未参与共享、被隐藏和实时追踪的项。快照功能只读，保存或查看快照不会写入模型，也不会自动恢复快照。未提供可读值的项明确显示「不可读取」，不会用零或旧值代替。快照保存在数据目录下的 `snapshots/` 中；分发包不包含个人快照。

## 配置、导入与导出

默认数据目录是当前 Windows 用户的 `%LOCALAPPDATA%\AvatarSwitchSync`，升级程序不需要覆盖用户数据。使用「文件 → 打开数据目录」可查看。

- `config.json`：分组、模型成员、参数选择和可选名称映射。
- `state.json`：各共享组的参数保存值。
- 程序旁存在 `portable.flag` 时，改用旁边的 `data/` 文件夹，适合便携使用。

「导出分组配置」只导出分组定义，**包含所选模型 ID**，不含参数保存值和运行日志。导入会检查格式、重复模型和重复参数，分配新的组标识，避免套用无关的历史状态；不会静默替换现有分组。

## 分发

请使用干净分发包。不要将自己使用中的 `data/`、`portable.flag` 或日志重新压缩发给其他人。本机便携版保留个人设置，不能直接作为公共分发包。

本工具没有联网账户、遥测或自动上传。同步通过本机 OSCQuery 与 mDNS 发现；更新检查只请求 GitHub 的公开版本信息，下载安装前需要用户操作。

## 限制与排查

外部恢复采用约 3 秒的等待及最多 3 次确认，不包含模型内部就绪握手。其他插件稍后初始化仍可能覆盖参数；它不恢复动画进度、物理姿态和插件计时。

找不到模型时，在游戏中加载模型并开启 OSC 后刷新。无法连接时检查游戏 OSC 开关，并查看「运行记录」。恢复未确认的参数会暂停记录，保留之前的共享值。删除共享组不修改游戏模型，历史保存值也不会自动删除。

## 源码和构建

源码包包含界面、连接、状态机与配置校验模块。使用 Python 3.12，依赖版本见 `requirements.txt`。可用 PyInstaller 构建为 Windows 桌面程序。

测试覆盖状态切换、初始化覆盖保护、类型检查、并集范围、静态眼追设置、配置导入校验、空白首次启动、持久化、运行中编辑锁以及窗口布局。界面和分发改动没有替代真实游戏中的兼容性验证。

官方接口：[OSCQuery](https://github.com/vrchat-community/osc/wiki/OSCQuery)、[OSC 眼追](https://docs.vrchat.com/docs/osc-eye-tracking)。

## SteamVR 启动时共享

安装时可勾选「SteamVR 启动时自动打开并开始共享」。下次 SteamVR 启动会打开软件并开始共享；VRChat 尚未连接时会等待。软件已打开时通知已有窗口开始共享，正在共享时不重复启动。普通双击打开仍需手动开始。SteamVR 自动启动时恢复已有共享记录；手动点击开始共享时先保存当前模型参数。自动启动会跳过没有记录的参数；完全没有可恢复记录时，提示先手动保存参考模型。

可在 SteamVR 的启动应用设置中关闭 Avatar Switch Sync；也可运行程序加 `--steamvr-disable-autostart` 参数关闭，再用 `--steamvr-enable-autostart` 开启。卸载会关闭此启动项，不影响分组和保存值。

## GitHub 更新

通过「帮助 → 检查更新」或右上角检查按钮查看新版本。启动时会在后台检查一次；失败时不弹窗打断共享。新版下载后会校验大小与 SHA-256，再由用户点击「安装并重启」。会先正常停止共享、等待程序退出，再升级到原目录；配置、共享值、参数快照均保留。更新前正在共享时，重启按恢复已有记录的方式继续。
